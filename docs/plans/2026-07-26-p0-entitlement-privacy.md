# P0: единый entitlement gate и прозрачность cloud-маршрута

## Пользовательский результат

Любой способ распознавания подчиняется одному правилу доступа и одной квоте.
Облачная обработка не маскируется под offline-режим и не включается неявно.

## Acceptance criteria

### AC1. Один gate для распознавания

- `LicenseManager.check_transcription_entitlement(required_seconds)` является
  единой точкой проверки полной лицензии и trial.
- Push-to-talk и обработка файлов вызывают этот метод до начала работы.
- Trial не запускается в обход обычного `check_access()`.

### AC2. Квота файлов

- До запуска batch известная длительность файлов сравнивается с остатком trial.
- После успешной транскрипции длительность результата списывается ровно один раз.
- Ошибка и отмена не списывают время как успешно обработанный файл.

### AC3. Квота активной записи

- Для trial запись автоматически останавливается при исчерпании доступных секунд.
- Таймер привязан к operation token и не может остановить следующую запись.
- Длительность считается через monotonic clock.

### AC4. Authoritative negative

- Ответ сервера `not_found`, `deactivated` или `expired` при ревалидации очищает
  локальный license cache.
- Ошибка сети или сервера не стирает ещё действующий offline cache.
- Повреждённый cache удаляется и не даёт доступ.

### AC5. Startup revalidation

- При старте устаревший cache ревалидируется в фоне, без блокировки первого окна.
- После authoritative negative следующий entitlement gate закрывает доступ.

### AC6. Privacy defaults

- OpenRouter STT передаёт `provider.data_collection = deny`, как и chat.
- Crash report сохраняется локально, а отправка выключена по умолчанию.
- README описывает фактические local/cloud маршруты и не обещает `100% offline`.

## Не входит в клиентский P0

- Асимметрично подписанные короткоживущие claims требуют серверного issuer,
  ротации ключей и нового формата токена. Клиентский HMAC нельзя считать корнем
  доверия; его замена выполняется отдельной совместной миграцией API и клиента.
- MindType Cloud STT не добавляется заглушкой: нужен стабильный upload/job API с
  idempotency, retention и provider-neutral schema.

## Lead Architect Report

### Границы

- `LicenseManager` владеет решением «можно ли начать» и очисткой cache.
- UI только показывает блокирующий диалог и планирует quota timer.
- `FileTask` хранит факт списания, чтобы повторный callback был идемпотентным.
- Провайдер владеет privacy-параметрами конкретного сетевого запроса.

### Инварианты

1. Неактивный entitlement не начинает ни диктовку, ни batch.
2. Authoritative negative не сосуществует с активным локальным cache.
3. Один завершённый файл списывается не более одного раза.
4. Opt-in — действие пользователя; предварительно отмеченный checkbox им не является.

### Риски

- Оценка длительности до batch может быть недоступна для повреждённого файла:
  такой файл проверяется в worker, но остальные не блокируются.
- Фоновая ревалидация допускает короткое offline-окно до ответа сервера; это
  сознательный компромисс ради запуска desktop UI без сетевой задержки.
- Жёсткий quota timer ограничивает запись, но сервер всё равно обязан независимо
  проверять quota для cloud jobs.
