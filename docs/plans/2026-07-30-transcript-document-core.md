# Сохраняемое ядро документов MindType

> Статус: спецификация первого вертикального среза.
> Дата: 2026-07-30.

## Цель

Превратить одноразовый `TranscriptionResult` в сохраняемый документ MindType:
исходная расшифровка остаётся доступной после перезапуска приложения, изменения
имён собеседников создают новую версию расшифровки, а несколько саммари могут
быть сохранены для одной записи без повторного распознавания речи.

## Не входит в этот срез

- Новый экран библиотеки и полноценный редактор расшифровки.
- Переназначение отдельных реплик и разделение одного собеседника на нескольких.
- Синхронизация документов между устройствами.
- Командные шаблоны и корпоративный Processing Endpoint.
- Удаление существующих BYOK/local-провайдеров.
- Перенос или копирование исходного аудио в хранилище MindType.

## Публичный контракт

Новый модуль предоставляет:

- `TranscriptStore(db_path)` — локальное SQLite-хранилище с автоматическим
  созданием и версионированием схемы.
- `save_result(result)` — сохраняет существующий `TranscriptionResult` как
  `TranscriptDocument` с первой неизменяемой `TranscriptRevision`.
- `get_document(document_id)` и `list_documents()` — читают документы только
  через доменную модель, без необходимости знать SQL-схему.
- `rename_speakers(document_id, names)` — создаёт следующую ревизию, не меняя
  историю предыдущей.
- `add_summary_variant(...)` — сохраняет независимый вариант саммари с привязкой
  к конкретной ревизии и снимку шаблона.

Доменные объекты:

- `TranscriptDocument`: стабильный ID, метаданные источника, текущая ревизия,
  сохранённые варианты саммари.
- `TranscriptRevision`: номер версии, сегменты, обработанный текст и отображаемые
  имена собеседников.
- `SummaryVariant`: содержимое, ID/имя/версия шаблона, снимок четырёх промптов,
  провайдер, модель, метрики и дата создания.

## Acceptance criteria

- **AC1 — переживает перезапуск.** Сохранённый результат можно открыть новым
  экземпляром `TranscriptStore`; сегменты, таймкоды, язык, модель, обработанный
  текст и имена собеседников совпадают.
- **AC2 — история собеседников неизменяема.** Переименование собеседника создаёт
  ревизию `N + 1`; исходная ревизия остаётся доступной, текущей становится новая.
- **AC3 — несколько результатов без нового STT.** К одной ревизии можно добавить
  два саммари с разными снимками шаблонов; документ и сегменты не дублируются и
  не изменяются.
- **AC4 — воспроизводимый шаблон.** Вариант хранит собственный снимок промптов и
  версию шаблона; последующее изменение пользовательского пресета не меняет уже
  сохранённый вариант.
- **AC5 — совместимость.** Если исходный `TranscriptionResult` уже содержит
  `summary`, оно импортируется как первый вариант. Старые свойства и существующая
  генерация HTML/PDF продолжают работать.
- **AC6 — безопасный сбой.** Повреждённый JSON отдельной записи или неизвестная
  будущая версия схемы дают явную доменную ошибку, а не частично заполненный
  документ. Запись одной операции атомарна.
- **AC7 — источник не обязателен для чтения.** Документ открывается, даже если
  исходный медиафайл был перемещён или удалён; путь хранится как метаданные.
- **AC8 — автоматическое сохранение.** Успешная файловая задача автоматически
  получает ID библиотечного документа. Ошибка локального хранилища логируется и
  добавляет предупреждение, но не превращает уже завершённую транскрипцию в
  ошибку и не блокирует существующий экспорт.
- **AC9 — файл базы освобождается.** После каждой публичной операции SQLite-
  соединение закрывается; на Windows файл базы можно сразу переместить для
  обновления или резервной копии.

## Edge cases и допущения

- В первом срезе сегменты и снимки шаблонов хранятся JSON-полями в SQLite. Это
  сохраняет простой публичный контракт; нормализация по словам и репликам
  откладывается до появления поиска/редактора.
- Пустой результат без сегментов не сохраняется.
- Имена неизвестных `speaker_id` разрешено добавить: это не меняет сегменты и
  позволяет принять исправления до полной переразметки.
- Смена имени на пустую строку отклоняется.
- `Path` сохраняется как абсолютная строка, но существование файла не проверяется
  при чтении.
- Временные ID создаются UUID4; порядок списка документов — сначала новые.
- Встроенные и пользовательские пресеты пока передаются как снимок при создании
  варианта, а не мигрируют в отдельную таблицу шаблонов.

## Вероятные файлы

- `app/transcript_store.py` — доменные модели, ошибки и SQLite-контракт.
- `app/transcription_models.py` — только минимальная совместимость, если она
  потребуется для связи сохранённого документа с текущей очередью.
- `app/main.py` — сохранение успешного результата; не должно содержать SQL.
- `tests/test_transcript_store.py` — поведенческие тесты публичного контракта.
- Существующие тесты `test_file_transcriber.py` и `test_report_generator.py` —
  регрессии совместимости.

## Трассируемый тест-план

- AC1 → `test_saved_result_can_be_loaded_by_a_new_store`
- AC2 → `test_renaming_speakers_creates_an_immutable_revision`
- AC3 → `test_two_summary_variants_share_one_transcript_revision`
- AC4 → `test_summary_variant_keeps_its_template_snapshot`
- AC5 → `test_existing_result_summary_is_imported_as_first_variant` +
  существующие тесты отчётов и транскрибера
- AC6 → `test_unknown_schema_version_is_rejected` и транзакционный сценарий
  добавления варианта к неизвестной ревизии
- AC7 → `test_document_load_does_not_require_source_file`
- AC8 → `test_completed_task_is_saved_to_the_transcript_library` и
  `test_store_failure_does_not_change_completed_task_status`
- AC9 → `test_store_releases_database_file_after_operations_on_windows`

## Проверка среза

1. Каждый критерий проходит отдельным RED → GREEN циклом.
2. Запускается новый тестовый модуль.
3. Запускаются регрессии транскрибера, пресетов и генератора отчётов.
4. Затем запускается весь pytest-набор.
5. База, созданная тестами, находится только во временном каталоге pytest.
